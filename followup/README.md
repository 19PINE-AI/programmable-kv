# Follow-up: neuron-level anatomy of the note (Nov 2026)

This directory holds the follow-up mechanism study behind **Appendix "Neuron-level anatomy of the
note"** (`app:neurons`), Figure `fig10_neurons`, Table `tab:additivity`, and the new sentences in
§3 (mechanism), the abstract, introduction, related work, limitations and conclusion.

It asks three questions on Llama-3.1-8B-Instruct (Qwen3-8B replicates steps 2–3):

1. **Who writes the note?** Attention vs. MLP at the note (aggregator) positions, then MLP neurons.
2. **Do a few neurons carry it?** Attribution concentration, top-k neuron patching, activation sign,
   joint vs. one-at-a-time ablation (T1b).
3. **Do neurons that *read* as clean *explain* it?** LLM labels for the top-100 neurons, then Gao's
   simulation–substitution test: replace a neuron's real activations with activations an LLM predicts
   from its label, and check how much of the effect survives.

`REPORT.md` is the full write-up with every table. `fig10_neurons.png` is a PNG preview of the paper
figure.

## Setup and conventions

- **Model:** `unsloth/Llama-3.1-8B-Instruct` (same weights as the paper's
  `unsloth/Meta-Llama-3.1-8B-Instruct`), bf16, sdpa. Qwen3-8B for the replication.
- **Pairs:** the polarity task's full 2×2 (`esys/mechd_common.POL`, `esys/circuit_common.py`):
  3 scenarios × 4 order ids × 2 field values = 24 SAFE/UNSAFE pairs with the field byte-identical.
  Neurons are ranked on 3 order ids (18 pairs) and tested on all 24; order id D5567 is held out.
- **Score:** S = logit[safe] − logit[unsafe] at the decision token, normalized by S_SAFE − S_UNSAFE.
  agg8 / agg1 are the top-8 / top-1 aggregator positions by KV-patch effect (`find_aggregators`).
- **Neuron:** one SwiGLU intermediate unit (input to `mlp.down_proj`); 32 × 14,336 = 458,752.
- **T1b numerics:** decision logits in fp32 from the final hidden state; baselines use the same padded
  batch size as the ablated runs (bf16 batch numerics otherwise add a +0.06 bias).
- **Labeller and simulator:** MiMo-v2.6-pro through an OpenAI-compatible endpoint. `t1_mimo.py`
  reads `MIMO_URLS`, `MIMO_KEY_2`, `MIMO_KEY_3` and `MIMO_MODEL` from the file named by `$MIMO_ENV`
  (default `~/clean-tests/mimo.env`). No keys are stored in this repo.
- **Paths:** scripts find the repo through `PKV_REPO` (default: two levels up from `scripts/`) and
  write to `FOLLOWUP_OUT` (default `followup/results`).

## Related context (not cited in the paper)

A separate audit of 500 random MLP neurons each in Qwen3-32B and Qwen3-1.7B found the same
legibility-vs-explanation gap outside this task: about 86% of Qwen3-32B neuron poles read as "one main
job", yet only 3.4% of the non-inert neurons pass the simulation–substitution test (simulation avoids at least 50% of
mean-ablation damage). That audit is not part of this directory.

## Caveats

- One model in depth; Qwen3-8B replicates only attribution and patching.
- The single-vs-joint neuron undercount (0.53) is borderline: the joint − sum CI includes 0.
- One labeller/simulator (MiMo-v2.6-pro), integer −10…10 scale and a linear calibration. A stronger
  explainer or simulator could do better.
